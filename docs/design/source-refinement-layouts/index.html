Source refinement — five ways to see the structure take shape

Five distinct, self-contained prototypes of the shared view accepted for source refinement: “During source refinement, a person can inspect the evolving system description alongside the conversation.” Each is a complete page with working interactions, and each demonstrates the same small cast of records — so the five can be compared like for like. One designer (GLM-5.3-Flash, via OpenCode) produced them as conversation moves for human reaction; none is a chosen direction, and nothing here is decided.

Iteration two — after Ben’s review. Ben selected Folio as a useful starting point and corrected its structure: Provenance already knows what creates what, so the page must nest. See Folio, nested — source refinement for product work, rebuilt around the real creation chain: each requirement holds its decisions, each decision holds what it produced and the requirement it spawned, and rules with no producing decision sit directly on their requirement. It now also wears the current provenance.sh identity — black ground, lavender ink, rose and gold accents, Cormorant Garamond with Fragment Mono (OFL copies bundled in fonts/). What is agreed, what is invented here

agreed  marks content recorded in the graph: the anchor requirement (source refinement organizes source material into an evolving system description), the shared-view requirement above it in this page, two approved decisions (the purpose, and showing the description beside the conversation), the open question about a requirement page with collapsible sections, and the source — the product discovery conversation of 4–6 September 2026 — with two verbatim passages: “It could be any source. I am just giving a scenario.” and “The goal is structure.”

illustrative  marks content minted for these prototypes only: one sub-requirement, one proposed rule, the editing-behaviour question, and every sample discussion line. A suggestion by the designer or an agent is never labelled as Ben’s decision. The rule is marked as a rule may be marked in earnest: produced by no decision (none is required), with no implementation and no verification.

Citations everywhere use the concept that exists today — a source plus a free-text clause. The designs do not invent a universal passage locator; general anchoring and source versions stay with the separate future shaping task. Every page carries a slim prototype banner, so the demonstration state is clear outside the product flow.

The five proposals

  1. i.
    Folio — the standing document
    The collapsible requirement document taken seriously: one requirement as the page subject; sub-requirements, candidate rules, decisions, open questions and attached sources as its numbered collapsible sections; discussion beside the page, bound to the selected record; inline editing tried where the editing question lives.
    tradeoff — collapsing hides the very evolution the view must expose; the outline carries the load when sections close.
  2. ii.
    Atlas — the constellation
    The graph form, named in the accepted decision, worked through: records keep their types and real relations — refines, resolves, spawns, cites — drawn as a selectable constellation. An agreed-only mode dims everything invented. The document is derivable; the shape is primary.
    tradeoff — reading rationale inside a side panel fragments prose, and the layout must be tended as the graph grows.
  3. iii.
    Margin — manuscript and scholia
    The description reads as one continuous text; provenance, status and the discussion live in the margin beside the passage they concern. Nothing collapses — statement and dissent share one glance, the most literal reading of “alongside the conversation”.
    tradeoff — margins force short contributions and cannot nest; narrow screens break the sideways glance.
  4. iv.
    Ledger — the landing stream
    Evolution-first: the primary object is the stream of landings, each entry pairing the conversation that caused it with the structure that moved. The standing page is derived — “as it stands now”, every line traced back to its entry. Steering is reacting to the pending entry.
    tradeoff — newcomers read history before content; “what is true now” costs one click and an act of assembly.
  5. v.
    Trestle — the passage workbench
    Citation as the spine: the source on the left, addressable passage by passage; the forming description on the right; a citation in either direction is a live bridge between them. The conversation docks under the passage it discusses.
    tradeoff — needs well-segmented sources and gives each side less room; finer anchoring stays deliberately out of scope.

Shared open questions the pages react to

These are carried in the demos rather than hidden: should the first shared view be a requirement page with collapsible sections or the graph form; what the editing behaviour is when the person and the agent both change the page; and the fog the anchor requirement already carries — the minimum structure that gives a product or engineering team useful direction is not yet clear. The demonstrations also show what the ontology distinguishes: a rule can exist before implementation, and a decision is not required to produce one.

Practical notes

Each page is a single HTML file with embedded CSS and JavaScript — no build step, no network dependencies, system font stacks only. Open directly from disk or serve the folder statically. Interactions (collapse, selection, contextual discussion, citation detail, local edits) run entirely in the page and persist nothing; they demonstrate behaviour, not storage. Ben’s verbatim words appear only in the two cited passages. The coordinating session owns graph tracking and ratification; these files change no graph records, skills, or production code.
