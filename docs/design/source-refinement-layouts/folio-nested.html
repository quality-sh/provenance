About this iteration — the correction, the projection assumption, what is invented

The correction

Ben accepted Folio’s document direction and corrected its structure: Provenance already knows what creates what, so the page must nest. The flat buckets are gone. A requirement’s document now holds its Resolutions; each Resolution holds what it produced and the requirement it spawned; that spawned requirement holds its own Resolutions and rules in turn — the creation chain, legible as indentation.

The relations shown

Requirement → refines one requirement, spawned by one Resolution, cites sources. Resolution → resolves one or more requirements, spawns requirements, produces rules. Rule → refines one or more requirements; its producing Resolutions are optional, so a rule with none nests directly on its requirement. Topic → anchored at its requirement; questions belong to the topic and to the requirement, and link to a resolving Resolution without owning it.

Design assumption (labelled, not decided)

When a record has more than one parent, this page nests it once, in its creation chain, and shows its other relations as labelled reference lines (“refines … · spawned by …”). Here the shared-view requirement both refines the root and was spawned by its Resolution — it nests under that Resolution, with the refinement named on the record. A requirement resolved by two Resolutions (the shared view, by the editing and reuse Resolutions) lists both. The alternative — repeating the record under every parent — would duplicate it; nothing here is duplicated.

Editing model (selected by Ben)

Existing records: click an editable field to change it in place — no modal. Free text edits as Markdown (the editor uses a monospace input as the Markdown cue); constrained fields, like lifecycle status, become dropdowns with the real closed vocabularies; relationship targets open a fuzzy search restricted to compatible records — the Rule here can only target Requirements. Change viewing has exactly two states — Before and After — on the statement of “Direct editing of sources and records”: Before shows the working version the change replaced, After shows the result, and After is the normal viewing state. The switch is purely visual; it never cancels or reverts the saved edit. Editing itself stays separate: Keep commits the typed text and rotates the prior version into Before, Cancel discards the draft. No third state and no diff mode. Creating a new item would open an editable dialog before the page changes — not demonstrated here. Everything is prototype-local and reversible by reload.

Type at document scale (proposal for review)

Correction applied: the hero treatment no longer runs through the working document. Cormorant Garamond is now display type only — the page title, record titles, and each record’s statement — with record titles stepping down by structural depth (26px at the root to 16px at the deepest, one steady size for statements). Everything read for length (fields, threads, notes, controls) uses a humanist UI face at 12–15px with normal letter-spacing; Fragment Mono is reserved for technical micro-text — depth markers, the breadcrumb, message locators. Secondary text is lifted to a lighter lavender for contrast, and competing borders are reduced to one divider per record plus the panel and inputs. This split is this prototype’s proposal for visual review.

Style provenance

Identity from the current Provenance web: black ground, lavender ink, rose, rose-gold and gold accents, fine low-contrast rules, Cormorant Garamond with Fragment Mono. The marketing hero, background animation and copy stay out of the editor. Both faces are SIL Open Font License; the bundled copies sit in fonts/ beside this file with their licenses, so the page still works offline.

Agreed vs invented

Agreed, from the coordinator: the root requirement, the five approved Resolutions, the four spawned or refined requirements, their statements and the page-form question. Invented for this prototype: the illustrative rule, both sample threads, the topic’s second question (source-edit versioning), the projection rule above, and every local edit. The original discovery conversation supports the root; the Resolutions cite this ongoing session, and the record labels keep the two sources apart.
