## Things checked and found fine

**Concurrency.** The guard is held across the whole pass: `catch_up_state` and `freshness::catch_up` acquire it before the pool opens and drop it after the pass returns; the rebuild path (`materialize_with_guard`) receives the same guard. No reader inside the pass takes a second lock: every read goes through the `GuardedStore` whose inner store carries `Access::Held`, so `state_path_access`/`with_repository_read` return without locking; `GuardedStore` is not `Clone` and the compile-fail proof moved onto the `under_guard` constructor (doctest passes). A canonical writer cannot interleave at all (it needs the lock the pass holds); an unlocked editor between hash and parse, or between parse and second hash, is caught by `stable`'s hash-again — the accepted pair is always (parse, digest-of-that-parse) from the same attempt, and the stored digest always describes the parsed bytes (R-2). Retries exhausted → the unit bails, the transaction is dropped uncommitted, and the read answers at the stored serial with `catch_up_failed` (R-4). The manifest read is race-free in both branches: the unchanged global parses the exact bytes retained by the global hash (`digest_with`'s `retain` hook), and the changed global re-parses through the store inside the same retry loop that re-hashes. Scope drift (a scope added or removed by an unlocked editor mid-pass) converges on the next pass because the scope list comes from the hashed manifest bytes and every other unit's digest is re-checked.

**Crash safety.** A rebuild writes `clear_cache`, all rows, the revision row, and the `projection_validation` row in one transaction (`materialize_with_guard` → `write_stamp`), so a mid-rebuild death rolls back to the previous consistent projection; nothing half-built is visible. The migration transaction commits 023 together with `forget_digests`, so the post-migration/pre-rebuild window has no digest rows and no validation row: the next catch-up rebuilds (`version_changed` treats a missing row as changed), and `annotate_only` refuses (`validation.is_none_or(… < …)`). The pre-existing crash tests (`catch_up_before_commit`, `catch_up_after_commit`, migration-window `annotate_only` refusal) still pass.

**Validation skipping.** The one behavior change the plan licenses is implemented as specified: an unchanged scope is neither parsed nor validated (`an_unchanged_pass_parses_no_shard_but_the_manifest` asserts the exact read set is the manifest alone); a changed scope alone is validated (and provably refused when its bytes are invalid); a global change validates every scope (`a_manifest_change_validates_every_scope` — the invalid scope refuses, nothing commits, serial unchanged). The version gate forces the rebuild: rewinding the stored version routes catch-up to a full rebuild that restores damaged tables and bumps the serial once (R-3), refuses an unchanged invalid scope during the upgrade, and `annotate_only` refuses the older projection outright (`annotate_only_refuses_a_projection_from_an_older_validator`). One process caveat, per plan and not a defect: nothing mechanical forces a validator change to bump `VALIDATION_VERSION`; the constant moves only if the release does it.

**The merge commit.** Only `rule.jsonl` needed resolution (it is the single file both sides touched); everything else from main landed verbatim, and `git diff 6923628 5eb1908` contains only the branch's intended files — nothing from main was lost. Record integrity of the shard is exact (R-1); only ordering is wrong (M-1). `.beads/interactions.jsonl` took main's one addition cleanly.

**The four rule records.** Ids 52, 47, 45, 42 characters — all under 55. Each states one atomic behavioural obligation. All four refine the real, active `req_query_answers_carry_a_freshness_stamp`, whose `source_refs` already cite the W5 plan revision 3. `#[rule]` sits on the primary implementation of each (`UnitReader::new`, `UnitReader::global`, `stable`, `version_changed`) and `#[verifies]` binds the evidence tests. The clean coverage scan names none of the four ids in any warning (R-5) and the warning list is identical to the base binary's.

**Declared departures.** All five are implemented as described and sound: parsed records held until the second hash matches (see N-2); scope discovery from the retained manifest bytes (race-free by construction, guarded by `a_manifest_restored_before_hashing_keeps_its_scopes` — the RED case the earlier review found); `units_hashed` unchanged in meaning (one increment per scanned unit, verification hashes excluded — same values the old `hash_unit` produced); eighteen families is correct (`ProjectionFamily::ALL` has 18; the plan's "nineteen" counted the relations table, which is not a family and carries no digest row); the unsupported-entry refusal moved from the deleted `copy_tree` into the hash walk and is stricter than before — the old in-place walk silently skipped a non-file entry, the new one bails (`units.rs:116-118`), and a symlinked walk root is refused too (`units.rs:92-95`), with `a_unit_with_a_symbolic_link_is_refused_before_parsing` guarding it.
