**Verdict: ACCEPT WITH AMENDMENTS.** The diagnosis is true and, on one point, understated: the journal is not merely inert, it is a pessimizer (a journaled write whose bytes are byte-identical still forces a re-derive). Per-scope hashing plus one global unit covers every reader input. But the ADR as written has one correctness hole (unit-to-table mapping for edges), one internal contradiction (it deletes the rows the W1 revision digest is computed from), and one serial-semantics coupling to W3 cursors that it silently bakes in. Amendments, precisely:

- **A1.** State the unit-to-table mapping: a scope unit owns the 18 scoped tables filtered by `scope_id`; the global unit owns the `edges` table whole. Never `DELETE FROM edges WHERE scope_id = X` on a scope change or scope departure.
- **A2.** Keep per-(family, scope) `content_digest` + `record_count` rows (they are derived from records, not a hand-maintained input mirror) and add the unit byte digest beside them; otherwise `revision_digest_from_stored_rows` cannot be computed for unchanged scopes without reparsing everything. Better still, adopt alternative (ii) below: hash per scope, and on a changed scope parse all 19 families but delete+insert only the families whose content digest moved.
- **A3.** Rule on the serial for a no-op pass: either "a pass that re-derives nothing, departs nothing, and adds nothing commits no revision row" (serial and digest stay), or record that W3 cursors bind to the digest, not the serial. Today's code and the ADR's "stored serial plus one" both bump the serial on every pass; under the W3 `catch_up` read policy that invalidates a revision-bound cursor between page 1 and page 2.
- **A4.** Add to the deviation list the bead-recorded human criteria the ADR supersedes: 2026-09-01 dispatch criteria 7 (journal keyed by declared family) and 8 (serial normalization precedes journal allocation), W5 stage 2 "journal default ON", the out-of-scope clause "journal emission inside the already-locked section", and the two serial-test rows in the acceptance checklist.
- **A5.** Record that the W1 `serial == 1` contract is restored (W2 relaxed it only because writer events consumed sequences before the first materialization) and restore those assertions.
- **A6.** Frame the relative path, not the file name, in the unit byte stream; name `state/dictionary.json` as a global-unit member; correct the description of the completeness gate; note that `merge/validation.rs::ShardFamily::for_shard_path` is a separate path→family mapping that stays.
- **A7.** Record the measured cost baseline (below) as what W5 measures against.

## Findings, most severe first

**1. ADR step 3 deletes edges it never reloads (correctness, in the ADR text).** Edges rows carry `scope_id` and are keyed `(scope_id, id)` (`crates/provenance-store/migrations/002_sources_requirements_edges.sql:22-31`), but the edges shard lives in the global unit. "Delete that unit's rows from all 19 family tables and reload the unit" applied to a scope unit deletes that scope's edge rows; the scope reload dispatches only the 18 scoped loaders (`crates/provenance-store/src/cache/materialize/family_rows.rs:160-204`); edges reload only when the global unit's digest moves. The current code avoids this by giving edges scope key `""` (`catch_up.rs:152-156`, `projection_families.rs:92-94`); the ADR must say so. Departed-scope semantics also need the statement: rebuild keeps edge rows for unmanifested scopes because `load_edges` loads the whole shard (`graph_records.rs:182-196`); the current `remove_departed_units` matches that (`catch_up.rs:231-262`); the new design must too or equivalence breaks.

**2. The ADR removes the rows the revision digest is built from (internal contradiction).** It says "one digest row per unit", "losing the per-family digest rows", and "the revision digest continues to derive from stored rows, as W1 defines it". W1's digest is a hash over per-(family, scope) content digests (`projection_digest.rs:139-171`) and `revision_digest_from_stored_rows` requires a non-empty `content_digest` for every (family, scope) (`projection_digest.rs:180-228`, migration 019). With only unit rows, an unchanged scope's per-family content digests are gone; the only way to stamp is to reparse every family every pass (`family_content_digests` — 32 ms release on this repo, O(bytes) always), which defeats "no reparse". Redefining the digest as a hash over unit byte digests changes the W1 contract (record-level → byte-level; a byte-only reformat would move it) and W1 property test 4. Keep the content-digest rows.

**3. Every pass advances the serial, including a no-op pass; the ADR fixes this in and W3 depends on it (remaining code + ADR).** `catch_up.rs:97,119` always inserts a new revision at `head`; `an_unchanged_pass_hashes_everything_and_rewrites_nothing` (`tests/catch_up_behavior.rs:126-153`) pins the digest but not the serial. The bead's 2026-08-28 02:36 comment treated exactly this behavior on PR 169 as a defect the worker was fixing. Dispatch criterion 3 makes cursors "request+revision-bound keysets" and the W3 consistency callout makes every read run the freshness step; combined, each page fetch would invalidate the previous page's cursor. Also the cause of deferred R2-E(ii) (unbounded `projection_revision` growth).

**4. The journal is a pessimizer, not just inert (supports the ADR; diagnosis understated).** `catch_up.rs:178-180`: `unchanged = digest matches && content non-empty && !drained.contains(key)`. I ran a probe at f121b55: a no-op `mutate_jsonl_records` on `sources` (bytes verified byte-identical before/after), then catch-up → `events_drained=1, families_rederived=1, rows_written=1`, with every `projection_family_digests` row and every table row identical before and after. The journal can only add work; it never changes an answer.

**5. ADR deviation list omits bead-recorded human criteria (A4).** `bd show provenance-1wh`, 2026-09-01 12:03 dispatch guidance items 7 and 8; plan W5 stage 2; plan section E "journal emission inside the already-locked section"; acceptance checklist rows "Serial restart after pruning…" and "Metadata-only comparison…" (leg two, "journal on with a drained window"). A future reviewer holding the bead would reject the implementing PR for missing criterion 7.

**6. Restored W1 contract not recorded (A5).** PR body ledger item 7 and the diff of `tests/projection_stamp_behavior.rs:148-158, 209-213`: `serial == 1` was relaxed to `head == serial + 1` / monotonic because journaled writer events consume sequences before the first materialization. Without a journal the first materialization is serial 1 again; the ADR should say so and the tests should go back.

**7. Framing (A6, minor).** `domain_bytes` frames `file_name()` only (`projection_families.rs:301-318`). A scope unit contains `implementations/binding.jsonl` and `verifications/binding.jsonl`; sorted full-path order still makes swaps detectable, but the ADR says "path and bytes" — frame the relative path and pin it.

**8. Gate description inaccurate (A6, wording).** The "completeness gate" is two tests that compare the declaration to a second hand-written list (`tests/journal_emission.rs:44-92`, `tests/catch_up_derived_state.rs:175-193`) plus `every_family_invalidation_reaches_the_projection`, whose `change_one_record` had to be hand-taught that cards derive from dispositions (diff of `tests/projection_digest_sensitivity.rs`, the `ProposalCards` arm). The ADR's conclusion (it cannot see the readers) is right; its description ("checks that declared files exist and that reference fields are declared") is not what the code does.

**9. Global-unit members not enumerated (A6).** Outside `scopes/` in `state/`: `manifest.json`, `edges/*.jsonl`, and `dictionary.json` (`crates/provenance-store/src/dictionary_reference.rs:10-12`, unread by any loader). Covered by construction; name them, and note a dictionary or manifest-only change reloads edges (harmless, ~200 KB here).

**10. Corrupt-database routing (remaining code, low).** Plan trigger 4 says open/migration failure routes to total rebuild; `catch_up.rs:42-44` returns the error (`open_cache`, `cache.rs:32-37`, only creates if missing). The 08-28 correction queue asked for "rebuild on cache open/migration failure". Likely W5 reader-policy scope; record it so it is not lost with the journal tests.

**11. `families_hashed` counts units (remaining code, cosmetic).** `catch_up.rs:223-227` increments per (family, scope); with two scopes the "19" in tests becomes 38. Rename to `units_hashed` when the unit changes.

## Answers

**1(a) Does the journal change any answer?** No. Its only effect on the sweep is `drained.contains(&key)` at `catch_up.rs:180`, which forces re-derivation from the same snapshot bytes; rows come from `family_rows::load_rows` off the snapshot either way (`catch_up.rs:186-187`). The serial is `normalize_head(stored)` (`catch_up.rs:61,97`), so journal events raise the serial number, but the stamp's meaning (monotonic within instance, `docs/cache.md:13-17`) is unchanged. Probe in finding 4 confirms rows and digests are identical with and without the hint; the plan's own leg tests (`catch_up_behavior.rs:180-260`) already show the hash finds every change with the journal deleted. No served result exists yet (no caller of `catch_up_state` outside the store crate).

**1(b) Hand-maintained mirror?** Yes for 17 of 19 families: `byte_domain` (`projection_families.rs:142-176`) is a hand-written match; `canonical_records` (`181-227`) calls `store.list_*`; nothing ties them. The two exceptions prove the alternative exists: messages and edges reuse the readers' own discovery functions (`readers.rs:320-345, 377-395`). The derived-field miss is real: `project_proposal_cards` (`state_store.rs:292-320`) calls `effective_proposal_state` (`core/model/ideation/lifecycle.rs:127-145`) over `list_assertion_records` and `list_dispositions` (which also reads `promotion_decisions.jsonl`, `state_store.rs:330-343`); before round 4 the declared domain stopped at cards + landings. The gate cannot see this because it compares two hand-written lists (finding 8).

**1(c) "A third" fair?** Counting the PR body ledgers: rounds 1+2 = 14 items (10 numbered, 3 deferred, 1 boundary), journal-specific: F4, F6, 9, E(i), E(iii), boundary = 6 (+ parts of 8 and 10). Round 3 = 13 items (8 mutations incl. M6b, items 8-12), journal-specific: M2, M6, M6b, M7, 8, 10, 11 = 7. Round 4 = 1, journal 0. Total 28, journal 13 = 46%. "A third" is conservative. The two rejection-grade findings (R1-F1, R4) are both the byte-domain declaration's. The six items the ADR names all appear in the ledgers.

**2(a) Cross-scope or global reads.** Traced every `list_*` and loader: sources through rules `read_jsonl(<scope shard>)` (`state_store.rs:148-172`); bindings `read_jsonl_closed` (`175-200`); reviews direct parse (`requirement_reviews.rs:115-128`); threads/messages (`246-251`, month shards under `scopes/<s>/threads/`, `readers.rs:320-345`); five ideation families overlay `scopes/<s>/ideation/landings.jsonl` (`ideation_batches.rs:23-28`); dispositions add `promotion_decisions.jsonl` (`330-343`); cards derive from assertions + dispositions (same scope); edges read `state/edges/*.jsonl` (`readers.rs:377-395`). The manifest is read by `validate_ideation_scope` for `disposition_actor_ids` (`ideation_batches.rs:126-131`) — validity only, and the validator runs every pass — and by catch-up for the scope list. No loader reads another scope's files; none reads `dictionary.json`. A per-scope unit plus one global unit covers every input. The W4 branch has no journal or serial reference (`git grep` on `origin/1wh-w4-relation-vocabulary`).

**2(b)** Not as written — finding 1. With A1 it is correct: families with global rows = edges only; cross-scope references exist only as ids inside rows (edge endpoints, `IdeationTarget`), never as derivation inputs.

**2(c) Serial as stored+1.** Nothing in W3/W5 reads journal sequences. `refuse_stale` "naming the gap between stamps" needs only serial/digest differences and which units moved (available from the sweep). `annotate_only` reads the stored stamp. The differential gate compares executors. The "rebuild serial covers every journaled write" property (`tests/materialize_guard_behavior.rs:127-153`) has no consumer. The one real coupling is finding 3 (cursors bound to a serial that bumps on every no-op pass), which exists today and the ADR must rule on.

**2(d) Cost to the W1 stamp contract.** Finding 2. The per-family `content_digest` rows (migration 019) must survive; only the shard `digest`, `size_bytes`, `mtime_ns` columns lose their purpose. "First pass after upgrade rebuilds once" is true but for a different reason: any applied migration routes to rebuild (`catch_up.rs:56-58`, pinned by `a_schema_move_routes_catch_up_to_a_full_rebuild`).

**2(e) Precision cost.** This repo's canonical state: 1,111,190 bytes, 17 files, one scope, 1,307 projected rows. Release-profile measurements on a copy (debug numbers were ~8x higher):
- guard + snapshot copy: 1.3 ms; hash all 19 domains (1.17 MB framed): 6.8 ms; validator per scope: ~11 ms; parse+canonicalize all 19 families: 32 ms.
- unchanged pass: 22-27 ms. One-family re-derive: 25 ms (boundaries, 3 rows), 29 ms (rules, 166 rows), 35 ms (contributions), 58-62 ms (proposal cards, 85 rows — the derived path parses three families).
- full re-derive = what per-scope costs on a one-scope repo: 105-128 ms.
So per-scope makes a read-after-write ~4-5x the unchanged floor and ~2-4x the per-family path, once per write. Linear extrapolation: at 10x (11 MB) floor ~0.25 s, per-scope re-derive ~1.1 s, per-family 0.25-0.6 s; at 100x (110 MB) floor ~2.5 s (hash 0.7 s + validator ~1 s + snapshot copy + baseline read), per-scope ~11 s, per-family ~0.3-6 s. Under the W3 `catch_up` policy the pass runs per read, so at 100x every read that follows a write pays ~11 s under the ADR versus ~2.5 s floor. The ADR is right that the hash is not the marginal cost; parse + row writes are, and per-scope pays all of them per write. Defensible at today's size (100 ms), not at 100x without alternative (ii). Note the floor itself is dominated by the validator and the snapshot copy, which the ADR keeps.

**3. What the ADR misses.** Findings 2, 3, 5, 6, 7, 9. Lost coverage that still matters and must be re-homed rather than deleted with the journal: writer-commit reaches the projection (`a_journaled_write_is_drained_and_matches_a_rebuild` becomes hash-detected); idempotence of consecutive passes (`draining_the_same_journal_twice…`); crash after commit (`a_crash_between_commit_and_head_fsync…` becomes "crash after commit, next pass finds nothing"); concurrent rebuild vs catch-up; total loss restarts at 1 inside a fresh instance; database lost → rebuild at 1. Straight deletions: `journal.rs` 9 unit tests, `journal_emission.rs` 8, nine journal-specific tests in `catch_up_serial_crash.rs`, one in `materialize_guard_behavior.rs`, one in `catch_up_validation_behavior.rs` (~28 of the 37 catch-up-family tests; suite green on f121b55, 37 passed). Also unrecorded: `CatchUpReport` loses `events_drained`; the `docs/cache.md` paragraph added by W2 (lines 20-33 of the diff) is rewritten; the plan's "families with no SQLite table are recorded but ignored" rule becomes moot; the leg-two same-size test collapses into leg one.

**4. Alternatives.**
(i) Instrument reads to derive domains: readers funnel through `read_records` (`readers.rs:157-181`, "the one place a stored line becomes a record") except `list_requirement_reviews`, which reads the file directly (`requirement_reviews.rs:115-128`), so an instrumented domain would miss reviews unless the instrumentation sits at the fs layer or that reader is fixed. Deeper problem: recorded domains are data captured at the last derivation; a new binary that reads a new file inherits the old domain for unchanged families until a rebuild — the same miss class, deferred. Needs a rebuild-on-binary-version rule. The ADR's rejection stands.
(ii) Per-scope hash, per-family re-derive by content digest: on a changed scope, parse all 19 families (32 ms here, the part `canonical_records` already does), compute content digests, delete+insert only families whose content digest moved. Saves the row writes (~70 ms of the ~110 ms full re-derive), keeps the content-digest rows A2 requires anyway, needs no mirror and no journal, and the equivalence tests apply unchanged. Cheaper than the ADR's choice, no new correctness surface. Recommend it as the shape.
(iii) Journal as an optional accelerator with no serial coupling: still needs a file→family mapping (the mirror) or per-scope events; per-scope events cannot skip the hash, and finding 4 shows the hint only adds work. Reject, agreed.

**5. Adversarial review of what remains.** Findings 3, 10, 11. Checked and defensible: guard capability (`guard.rs:68-111`; private field pinned by trybuild); read-only bypass returns a lockless guard by design (`guard.rs:79-81`) — a materialization under `with_read_only_validation` would run unlocked, same as the sync path, worth a doc line; snapshot readers lock the snapshot's own temp root via `with_state_path_access` (`publication.rs:441-456`), so no self-deadlock with the held guard; `delete_rows` formats only enum-static table names (`family_rows.rs:137-149`); validator runs on the snapshot for every manifest scope before any write (`catch_up.rs:73-75`); revision digest reassembly re-sorts and refuses empty content digests (`projection_digest.rs:185-188`); departed-unit removal handles a family name the current table no longer knows (`catch_up.rs:244-259`); manifest scope with no directory yields an empty digest and zero rows, matching rebuild; `INSERT OR IGNORE` instance id is only written by rebuild, which every catch-up presupposes.
